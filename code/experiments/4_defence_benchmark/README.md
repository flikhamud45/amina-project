# 4. The benchmark: both protocols and the path test (paper Sec. 4.2–4.6)

`bench.py` measures our protocol (`pvi.fullcheck`), in its basic and optimised forms, and the path
protocol of Anchuri et al., re-implemented on the same integer graphs (`pvi.fullcheck.sampling`), on
the image classifiers and language models of the paper. The prover runs on a GPU; the verifier runs
on the CPU, or on the prover's GPU with `--verifier-device cuda`. Nothing is aggregated here: every
measurement is appended, one JSON line per trial, to
`artifacts/comparison/raw_<platform>/<suite>/<model>/<cell>.jsonl`, where the platform (`--platform`
or `$PVI_PLATFORM`) names one GPU model and one CPU model. The stored runs, and which of them the
paper uses, are described in [`artifacts/comparison/README.md`](../../artifacts/comparison/README.md);
the stored roots are not to be extended, so a new measurement uses a new platform name. The tables
and figures are then made by [`5_comparison`](../5_comparison/README.md).

## Hardware and time

* **Prover:** one CUDA GPU. The paper's runs used an NVIDIA L40S (48 GB); a second run of the basic
  protocol used an RTX 2080 Ti (11 GB). A build that does not fit the card (Llama-2-13B in full on
  11 GB, Llama-2-70B in full on 48 GB) is skipped with a `SKIP` line, and its job then ends with an
  error after its other builds.
* **Verifier:** 8 CPU threads (the paper: AMD EPYC 9334). `bench.py` refuses records from a second CPU
  model in one root, so keep a root's jobs on one kind of node.
* **Host memory:** with `--lean`, Llama-2-7B at 2,048 tokens peaks at 7.3 GiB of GPU memory and 42 GiB
  of host memory (`gpu_peak_memory`, `host_peak_rss` in `raw_l40s/`). `slurm/bench.sbatch` asks for
  96 GB; the 13B jobs at 2,048 tokens need 128 GB.
* **Time:** a CNN or GPT-2 job takes minutes, the largest language-model jobs at 2,048 tokens one to
  two hours. The records of the basic run's 61 jobs span about 14 hours on the L40S nodes, without
  model building before each job's first cell and without queueing. Training the CNNs takes minutes
  for LeNet-5 and a few hours for the 224-pixel ResNets.

## 1. Train the CNNs (GPU)

```bash
python experiments/4_defence_benchmark/train.py --model lenet5 --device cuda
# models: lenet5 vgg11 vgg16 resnet18_cifar resnet18_224 resnet18_224_squirrel
```

Writes `artifacts/fullcheck/models/<model>.pt` and a JSON report (accuracy, epochs). These weights
are not included in this folder (they are regenerated by this step); retrained models are equally
accurate but not bit-identical, so accuracies and the attack cells may differ slightly from the
stored ones, while the basic protocol's costs depend only on the shapes. The data:

* LeNet-5 trains on MNIST, which torchvision downloads to `code/data/` on first use (needs network).
* The CIFAR models read CIFAR-10, in torchvision's `cifar-10-batches-py/` layout, from
  `code/data/cifar10/`, or from `$PVI_CIFAR_ROOT` when it is set. The code does not download it
  (`download=False`); fetch it once, e.g. with
  `python -c "from torchvision import datasets; datasets.CIFAR10('<dir>', download=True)"`, with
  `<dir>` either `data/cifar10` (run from `code/`) or another directory and `export PVI_CIFAR_ROOT=<dir>`.
* The 224-pixel dog-vs-cat and dog-vs-squirrel ResNets read ImageNet from `code/data/imagenet/`, or
  from `$PVI_IMAGENET_ROOT` when it is set, which must contain `train/` and `val/` with one folder per
  class, named by the class's 1-based index in sorted-synset order (dogs 152–269, cats 282–286, fox
  squirrel 336). ImageNet cannot be downloaded by the code.

The decoded ImageNet images are cached in `artifacts/fullcheck/cache/` (or `$PVI_CACHE`) on first use;
once the cache exists, ImageNet itself is no longer read. **On the cluster** the datasets are not under
`code/data/`: every CIFAR or ImageNet job, `slurm/smoke.sbatch` included, needs `PVI_CIFAR_ROOT` (and
`PVI_IMAGENET_ROOT`, unless the ImageNet cache exists) exported to the dataset's location before
`sbatch` ([section 4](#4-on-the-tau-slurm-cluster)). The MNIST MLP is
`artifacts/models/mlp_mnist_full.npz`, which is included (see [`0_train_models`](../0_train_models/README.md)).
The language models need no training: they use their exact shapes with random int8 weights.

## 2. Run the benchmark for one model (basic protocol)

```bash
export PYTHONPATH=$PWD/src PVI_PLATFORM=<new name>
python experiments/4_defence_benchmark/bench.py cnn --model lenet5 --queries 30 --tampers 100
python experiments/4_defence_benchmark/bench.py llm --model gpt2 --seq 64 128 256 512 --queries 10 --lean
python experiments/4_defence_benchmark/bench.py llm --model llama2-7b --seq 64 --builds 1,2,full --queries 10 \
    --lams 128 --modes C:int,Kpre:int --llm-tampers 30 --lean
```

These are the settings of the paper's basic run; the `must`, `should` and `nice` tiers of
[`slurm/strong_gpu.sh`](slurm/strong_gpu.sh) list every job. `--builds 1,2,full` builds the decoder
with 1 and 2 blocks and at full depth (the default builds decoders above 12 blocks only with 1 and 2
blocks). `--lean` streams the claims to host memory and frees dead tensors: the same integers and
proof, far less GPU memory. The CNN suite runs every mode at λ = 40, 80 and 128; the LLM suite the
modes and levels given by `--modes` and `--lams`. The Reed–Solomon rate is 4 throughout (also the
base rate of every commitment plan). A cell with a `.done` marker is skipped, so an interrupted job
can simply be restarted.

| Cell (CNN suite) | What it measures |
|---|---|
| `facts` | parameters, float and int8 accuracy |
| `attack_float` | the single-neuron flip on the float model (Sec. 4.2, *Larger models*) |
| `sampling` | the path protocol: exact detection per neuron, bytes for k paths (shared openings) |
| `defence_<mode>_<challenges>_lam<λ>_rate4` | honest queries: time per part, proof bytes by part, acceptance (modes C, K, Kpre; interactive `int` or Fiat–Shamir `fs`; λ = 40, 80, 128). The `defence_C_int_*` cells also run one query of 8 and one of 32 images in a single interaction (`--cnn-batches`, default 8 32) |
| `tamper_C_int_lam40` | seven attacks, with the check that rejected each one (Sec. 4.3) |

The LLM suite has `commit_*` cells (the one-time weight commitment) and `defence_*` cells per prompt
length and build (`_T<tokens>_L<blocks>`). Each defence cell also runs one tampered query (one
pre-activation of a middle layer changed by +1) that must be rejected. With `--llm-tampers N`, every
full build also gets a `tamper_C_int_lam40_<build>` cell: N each of `single_value` (one random
pre-activation changed by ±1 to ±999), `output_logit` (a wrong token given the top logit) and
`last_hidden` (one coordinate of the last block's output projection at the last position set to a
large value), and max(3, N/10) `substituted_block_1pct` (one random block with 1% of its weights
changed by ±1). The paper uses N = 30 at up to 64 tokens. With `--batches B ...`, the `C:int` and
`Kpre:int` cells also time B prompts against one set of challenges and openings (the `_batch` cells;
Sec. 4.4 quotes Llama-2-7B with 8).

**Options.** Both suites: `--queries` (honest queries per cell), `--threads` (verifier threads),
`--tag` (a cell-name suffix for variant runs), `--verifier-device`, `--verifier-impl`, `--wire`,
`--policy`, `--tf32`, `--batch-trials` and `--platform`. CNN suite: `--tampers` (attacks per type; 0
skips the tamper cell) and `--cnn-batches`. LLM suite: `--seq`, `--lams`, `--modes` (e.g.
`C:int,Kpre:int`), `--builds`, `--lean`, `--llm-tampers`, `--batches`, `--prune-last` and `--lookups`.
`python experiments/4_defence_benchmark/bench.py --help` describes each.

**Variant runs of the basic protocol** (the exact lines are in `slurm/strong_gpu.sh`):
`--verifier-device cuda` runs the client's checks on the prover's GPU (`_gpuv`: the basic protocol's
GPU verifier, Sec. 4.5); `--batches 8 32` or `--cnn-batches`, with `--batch-trials`, time several prompts
or images against one set of openings (`_batch`); `--threads 1` and `12` (`PVI_THREADS` under
`bench.sbatch`) give `_thr1` and `_thr12`; `--tf32` allows TF32 tensor cores in the float32 products
of the forward pass (`_tf32`; `bench.sbatch` needs `PVI_TF32=1` for it); the LLM jobs without
`--lean` are `_nolean`; and `PVI_LEGACY_WEIGHT_KEY=1` restores the weight cache of the earliest run,
which re-uploaded the committed weights to the GPU twice per query (`_nofix`). `bench.py` refuses
`--verifier-device cuda`, `--tf32` or `PVI_LEGACY_WEIGHT_KEY=1` without the matching tag.

## 3. The optimised protocol

The optimised protocol (paper Sec. 3.6.2) is the basic protocol plus the following options. The
verifier engineering is always on; without the other options `bench.py` runs the basic protocol,
whose verdicts, proof bytes, Fiat–Shamir transcripts and Merkle roots do not depend on the code
version (565 hardware-independent values of `raw_l40s_improved/` equal those of `raw_l40s/`). How
each option works, its soundness argument and its development measurements are in
[`6_improvements`](../6_improvements/README.md).

| Option | What it does | Cell suffix |
|---|---|---|
| (always on) | the verifier engineering: batched exact products, the encoded folded row evaluated only at the opened columns, int32 attention, int8 tensor-core products on a GPU, one copy back per check | none |
| `--policy <name>` | commit under a commitment plan of `pvi.fullcheck.plans` over the base rate 4 (exact column counts, Merkle trees shared by matrices of one codeword length, per-matrix codeword lengths): `tight`, `cnn<e>` or `R<rate>`, each also with the suffix `c` (wide matrices committed transposed, q/k/v and gate/up fused, embedding tables as Merkle lookup tables), or `auto` (the planning rule of the paper: the `c` plan with the fewest non-claim bytes within a setup budget of max(2 x the basic protocol's encoded entries, 2^34)). Only the commitment and the mode-C cells run; the chosen plan is recorded as the cells' `policy` | `_pol<name>` (added by `bench.py`) |
| `--wire` | the proof in the compact, lossless encoding of `pvi.fullcheck.claimcodec` (the encoder's `prove_encode` and decoder's `verify_decode` timed, the encoded `bytes_*` recorded) | needs `_wire` in `--tag` |
| `--prune-last` (LLM) | the last block computed at the last position only (keys and values at every position) | `_prune` (added by `bench.py`) |
| `--lookups` (LLM, K and Kpre) | the verifier reads the embedding rows itself and the prover sends no claims for them; runs the K and Kpre cells only (not together with `--policy`) | `_lookups` (added by `bench.py`) |
| `--verifier-device cuda --verifier-impl stream` | the streaming GPU verifier: claims uploaded one weight operation at a time and checked as they arrive; the same verdicts; records one `verify_total` per query instead of the verify phases it overlaps | needs `_gpuv` and `_stream` in `--tag` |

The paper's optimised cells combine these options as defined by `OPTIMISED` in
`5_comparison/paper_assets.py` (table in [`5_comparison`](../5_comparison/README.md#the-optimised-protocols-definition)).
For example, with the settings of the basic run:

```bash
B="python experiments/4_defence_benchmark/bench.py"
$B cnn --model lenet5 --queries 30 --tampers 100 --policy auto --wire --tag _wire     # C: planning rule + encoding, with the attacks
$B cnn --model lenet5 --queries 30 --tampers 0 --wire --tag _wire                     # K and Kpre (and C without a plan)
$B llm --model llama2-7b --seq 64 --builds 1,2,full --queries 10 --lams 128 --modes C:int --llm-tampers 30 --lean \
   --policy auto --wire --prune-last --tag _wire                                        # C, CPU verifier
$B llm --model llama2-7b --seq 64 --builds full --queries 10 --lams 128 --modes C:int --lean \
   --policy auto --wire --prune-last --verifier-device cuda --verifier-impl stream --tag _wire_gpuv_stream   # C, GPU verifier
$B llm --model llama2-7b --seq 64 --builds 1,2,full --queries 10 --lams 128 --modes Kpre:int --lean \
   --lookups --wire --prune-last --tag _wire                                            # Kpre
$B llm --model qwen3-4b --seq 8 --builds full --lams 40 --modes Kpre:int --lean --threads 1 \
   --lookups --prune-last --wire --tag _thr1_wire                                       # Maverick's setting
```

## 4. On the TAU SLURM cluster

`slurm/train.sbatch` and `slurm/bench.sbatch` wrap `train.py` and `bench.py` and pass their arguments
through. Submit them from the folder that holds `code/` (`$PROJECT_DIR`, by default the submission
directory): they `cd` into `code/`, put its `src/` first on `PYTHONPATH`, and use `$PROJECT_DIR/.venv`
unless `$PVI_PYTHON` names another Python; the commands below write the logs to `$PROJECT_DIR/logs/`.
`bench.sbatch` sets the verifier's threads from `PVI_THREADS` (default 8). The CIFAR and ImageNet jobs
(training, the CNN benchmarks and `smoke`) read the datasets from `$PVI_CIFAR_ROOT` and
`$PVI_IMAGENET_ROOT` ([section 1](#1-train-the-cnns-gpu)): export both to the datasets' location on the
cluster before submitting, since `code/data/` holds neither there (`sbatch` passes the exported
variables on to the job; `PVI_IMAGENET_ROOT` is not needed once the ImageNet cache exists). Train first
and wait for that job to finish, since the CNN jobs load the trained weights:

```bash
mkdir -p logs
export PVI_CIFAR_ROOT=<CIFAR-10 directory> PVI_IMAGENET_ROOT=<ImageNet directory>   # the datasets' location on the cluster
sbatch -o logs/%x-%j.out code/experiments/4_defence_benchmark/slurm/train.sbatch lenet5 vgg11 vgg16 resnet18_cifar resnet18_224 resnet18_224_squirrel
# when it has finished (squeue -u $USER):
export PVI_PLATFORM=<new name> SBATCH_PARTITION=killable SBATCH_GRES=gpu:l40s:1
bash code/experiments/4_defence_benchmark/slurm/strong_gpu.sh smoke   # once per GPU type: wait for SMOKE OK in its log
bash code/experiments/4_defence_benchmark/slurm/strong_gpu.sh must    # then should, then nice: the basic protocol
# a single job:
mkdir -p logs/$PVI_PLATFORM
sbatch -o logs/$PVI_PLATFORM/%x-%j.out code/experiments/4_defence_benchmark/slurm/bench.sbatch cnn --model vgg16
```

`smoke` (`slurm/smoke.sbatch`) runs every test on the GPU (none may be skipped; `tests/test_real_weights.py`
only where `transformers` is installed), loads every dataset (MNIST, CIFAR-10 and both ImageNet
subsets: hence the two variables above), runs small benchmarks into a throw-away root, and
`5_comparison/fingerprint_check.py` against `raw/`, whose hardware-independent values every new GPU
must reproduce. A job of a tier that is already queued is not submitted twice, and a pre-empted job is
resubmitted by running the same tier command again. On a partition whose nodes have different CPUs
(TAU's `killable` partition has one L40S node, t-806, with an Intel CPU), keep the jobs on one kind of
node, e.g. with an `sbatch` wrapper on `PATH` that adds `--exclude=t-806`. `PVI_DRYRUN=1` prints the
`sbatch` lines instead of submitting them; the header of `strong_gpu.sh` shows how to run them on a
machine without SLURM.

**The basic protocol (`raw_l40s/`)** is every job of the `must`, `should` and `nice` tiers, run with
`PVI_PLATFORM=l40s` on `killable` with `SBATCH_GRES=gpu:l40s:1`, at commit `9401431`.

**The optimised protocol, first batch (`raw_l40s_improved/`)** is the following list, run with the
same setup at commit `c8be5eb` (26 benchmark jobs; the tests ran as one more job). The Llama-2-13B
job of step 4 needs `--mem=128G`.

```bash
export PVI_PLATFORM=l40s_improved SBATCH_PARTITION=killable SBATCH_GRES=gpu:l40s:1
B=code/experiments/4_defence_benchmark/slurm/bench.sbatch; mkdir -p logs/$PVI_PLATFORM; L="-o logs/$PVI_PLATFORM/%x-%j.out"
# 0. the tests on the L40S (from code/): python -m pytest tests -q -p no:cacheprovider -o addopts=""
# 1. CNNs: the basic proof with the released code, then the planning rule, then the rule and the encoding
for m in lenet5 vgg11 vgg16 resnet18_cifar mlp_mnist; do
  sbatch $L $B cnn --model $m
  sbatch $L $B cnn --model $m --policy auto
  sbatch $L $B cnn --model $m --policy auto --wire --tag _wire
done
# 2. GPT-2: the basic proof, then the optimised one (CPU and GPU verifier)
sbatch $L $B llm --model gpt2 --seq 64 512 --lams 128 --modes C:int,Kpre:int --lean
sbatch $L $B llm --model gpt2 --seq 64 512 --lams 128 --modes C:int,C:fs --lean --policy auto --wire --tag _wire --prune-last
sbatch $L $B llm --model gpt2 --seq 64 --lams 128 --modes C:int --lean --policy auto --wire --prune-last --verifier-device cuda --tag _wire_gpuv
# 3. Qwen3-4B in Maverick's setting (1 verifier thread), without and with the encoding
PVI_THREADS=1 sbatch $L -c 1 $B llm --model qwen3-4b --seq 8 --builds full --modes Kpre:int --lams 40 --lean --lookups --prune-last --tag _thr1
PVI_THREADS=1 sbatch $L -c 1 $B llm --model qwen3-4b --seq 8 --builds full --modes Kpre:int --lams 40 --lean --lookups --prune-last --wire --tag _thr1_wire
# 4. zkLLM's models at 2,048 tokens: the streaming GPU verifier on the basic proof format
for m in opt-125m opt-1.3b opt-6.7b llama2-7b llama2-13b; do
  sbatch $L $B llm --model $m --seq 2048 --builds full --modes C:int,Kpre:int --lams 128 --lean --verifier-device cuda --verifier-impl stream --tag _gpuv_stream
done
# 5. Llama-2-7B at 1 and 64 tokens with the planning rule and the encoding
sbatch $L $B llm --model llama2-7b --seq 1 64 --builds full --lams 128 --modes C:int --lean --policy auto --wire --tag _wire
```

## Records

An honest query that is rejected stops the job and keeps that cell's records as
`<cell>.rejected-<run_id>.jsonl`, which `count_outcomes.py` counts. `gpu_peak_memory` is the prover
GPU's peak over a cell's queries (with `--verifier-device cuda`, prover and client together), and
`host_peak_rss` the peak host memory of the job's one process (prover and verifier). The timing parts
add up to the prover and verifier times (`prove_*`, `verify_*`; with `--wire` also `prove_encode` and
`verify_decode`; with lookup tables `prove_lookups` and `verify_lookups`); the streaming verifier's
`verify_total` replaces the verify phases it overlaps. `bench.py` refuses to run when the imported
`pvi` is not this checkout's `src/pvi` (for example a shared environment with another copy installed
in editable mode): `export PYTHONPATH=<this folder>/src`, as the sbatch scripts do. The stored roots
also hold metrics that no table or figure reads; they only enter the record totals.

An interrupted attempt leaves a cell's records in `<cell>.jsonl.part`; when the cell is restarted,
`bench.py` sets them aside as `<cell>.jsonl.part.<timestamp>` (the Unix time of the restart) and
writes the cell anew. These files are kept on purpose and read by none of the aggregates, which read
only the finished cells' `<cell>.jsonl` (see [`artifacts/comparison`](../../artifacts/comparison/README.md)).

**Contention evidence** (from commit `7016557`). Every timing row (unit `s`) of a query, a batch, a
commitment (`commit_total`), a build (`build_graph`) or a precomputation (`verifier_precompute`)
carries a `contention` field ([`pvi.fullcheck.contention`](../../src/pvi/fullcheck/contention.py)), the
evidence of whether the machine was quiet while that phase ran:

| Field | Meaning |
|---|---|
| `wall_s` | seconds between the two snapshots that bracket the timed window |
| `run_ns`, `wait_ns` | summed over this process's threads, nanoseconds spent on a CPU and waiting on a run queue (`/proc/self/task/<tid>/schedstat`) |
| `wait_frac` | `wait_ns / (run_ns + wait_ns)`: the share of the runnable time spent waiting for a CPU (0 on a quiet machine with enough cores) |
| `nivcsw`, `nvcsw`, `cpu_s` | involuntary and voluntary context switches and user + system CPU seconds of the whole process (`getrusage`) |
| `threads`, `threads_exited` | threads seen at the end; threads that ended during the phase (their run and wait times are lost, `cpu_s` keeps their CPU time) |
| `load_start`, `load_end` | `/proc/loadavg` at the phase's start and end: `[1 min, 5 min, 15 min, runnable now, tasks]` |
| `segments` | the number of parts the phase was timed in (a phase timed in parts sums their deltas) |

A value the system cannot provide is `null` (`run_ns`, `wait_ns` and `wait_frac` without
`/proc/self/schedstat`, e.g. on Windows or macOS). Each cell's `env` record carries `schedstat`:
whether the kernel reports these per-thread times. The snapshots are taken outside the timed windows,
so the field changes no timing, verdict or proof byte, and `aggregate.py`, `count_outcomes.py`,
`fingerprint_check.py`, `paper_assets.py` and `text_numbers.py` ignore it. The records of
`raw_l40s_improved3/`, the re-measurement of the withheld cells, are the first to carry it (every
other stored root predates it).
