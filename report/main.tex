\begin{abstract}
When a large model runs in the cloud, its users cannot tell whether an answer really
came from the agreed weights. zkSNARK proofs of inference solve this but take minutes
per query, so Anchuri et al.\ (SaTML~2026) proposed a lightweight alternative: the
server commits to the whole computation and the client re-checks one random path
through the network. We reimplement this protocol and break it by changing a single
neuron: the verifier still accepts the tampered answer 99.8\% of the time, and a
backdoor built this way costs nothing in clean accuracy. We
show that smarter sampling rules do not fix this. We then design
a new defence that checks \emph{every} layer at once. It verifies one random linear
combination per layer (Freivalds' check) against a Reed--Solomon/Merkle commitment to
the weights, in exact integer arithmetic. It catches any wrong value with probability
$1-2^{-\lambda}$ and needs no trusted setup. On models from LeNet-5 to Llama-2-13B it
rejected all 2{,}456 attacks and accepted all 5{,}547 honest queries. Its prover is one
to four orders of magnitude faster than published zkSNARK provers on the same models (as
reported on their own hardware). The price is a larger proof and a slower verifier.
\end{abstract}

\keywords{verifiable inference, proof of inference, integrity attacks, Freivalds' algorithm, zkML}

Suppose a company pays a cloud provider to answer its customers with a specific large
language model, for example a model it has licensed or fine-tuned. Every answer that
comes back is just text. Nothing in it shows that the provider really ran that model
with the agreed weights. It could have used a cheaper or more heavily quantised copy, a
model with a few weights edited, or a model that behaves normally except on certain
inputs. The customer cannot simply re-run the model to check: not having to run it is
the whole reason to use the cloud. A \emph{proof of inference} closes this gap. With
every answer the provider also sends a piece of evidence, and the client runs a cheap
check that passes only if the answer came from the agreed weights on this input.

The strongest proofs of inference are zkSNARKs~\cite{zkcnn,zkml,zkllm,zkgpt,deepprove}.
Their proofs are tiny and quick to check, but producing one takes far longer than the
inference itself. zkLLM, for example, needs about ten minutes on an A100 GPU for one
Llama-2-7B prompt~\cite{zkllm}. Anchuri et al.~\cite{anchuri2026verifiable} recently
proposed a much lighter approach. The provider commits to the full execution trace
(every activation) with a Merkle tree. The client then checks the computation along
\emph{one random path} from an output neuron back to the input, against a commitment to
the weights. Proving drops from minutes to milliseconds. The security argument is
statistical: a different model produces a trace that differs from the correct one in
many places, so a random path is very likely to hit one of them.

\para{What we did.} Our intermediate report started from one observation. Such a
scheme certifies that the served model is \emph{functionally close} to the committed
one, not that it \emph{is} the committed one, and backdoored
models~\cite{gu2019badnets} are the natural counterexample. We reimplemented the
protocol from scratch (no code was released) and reproduced its main claims. Then we asked what happens if the adversary does not
swap the model but changes only what it needs to. The answer is simple and severe. A
prover can run the right model, overwrite \emph{a single neuron}, and honestly
recompute everything after it (Figures~\ref{fig:overview-path}
and~\ref{fig:overview-attack}). The resulting trace is wrong in exactly one place. A
random path passes through that place with probability $1/N$ in a layer of width $N$,
so on our MNIST network the verifier accepts the tampered answer 99.8\% of the time.
Triggering the change only on chosen inputs gives a backdoor with no accuracy cost at
all on clean inputs. The paper notes that one path cannot detect a single changed node
with probability above $1/N$. It argues that this does not appear to be a practical
limitation for the substitute-model adversary it targets, and suggests sampling more
paths, or sampling adaptively, as mitigations. We show that the attack is practical, and
that neither mitigation repairs it cheaply.

This led us to a different design (Figure~\ref{fig:overview-defence}). Instead of checking a
few neurons exactly, we check \emph{every} layer at once with one random linear
combination of all its neurons (Freivalds' algorithm~\cite{freivalds1977}). When the
client does not hold the weights, it checks this combination against a
Reed--Solomon-encoded, Merkle-committed copy of them, in the style of
Ligero~\cite{ligero}. The client therefore still stores only 32 bytes per weight
matrix. To make the check exact, the model runs as an integer (int8) network that gives
bit-for-bit the same result on the provider's GPU and the client's CPU. The prover's
extra work is a fixed cost per query that does not grow with the input. The chance of
catching a wrong value, anywhere in the network, rises from $1/N$ to $1-2^{-\lambda}$.

\para{Contributions.}
\begin{itemize}
  \item \textbf{An attack} on the protocol of~\cite{anchuri2026verifiable}. Changing one
  neuron changes the answer. The verifier accepts the result with probability $1-1/N$
  (99.6--99.8\% on our MNIST model), including a trigger backdoor with zero clean-accuracy gap
  and 100\% attack success.
  \item \textbf{An impossibility argument} for sampling-based fixes. Uniform sampling is
  already the best rule that ignores the claimed values. The natural rule that looks at
  them has a blind spot, and our attacker reaches exactly zero detection through it.
  Reaching $2^{-40}$ forces the original protocol to open essentially the whole model
  and trace.
  \item \textbf{A new defence} with soundness error $2^{-\lambda}$ and no trusted
  setup. It covers whole CNNs (convolutions, pooling, residual blocks) and transformers
  (normalisation, GELU/SiLU, RoPE, softmax attention), with the weights either
  committed or known to the client.
  \item \textbf{A same-model evaluation} against the original paper and 17 other
  systems: 6 trained image classifiers and 7 LLM architectures up to 13B parameters.
  Every attack was rejected, and the prover is one to four orders of magnitude faster
  than the zkSNARKs as reported on their own hardware (17--47$\times$ against zkLLM on a
  stronger GPU). All code and raw measurements are released with this report.
\end{itemize}

\section{Related Work}

\para{zkSNARK proofs of inference.} A long line of work compiles neural networks into
succinct zero-knowledge proofs. For CNNs these include sum-check/GKR
provers~\cite{gkr} such as zkCNN~\cite{zkcnn} and zkPyTorch~\cite{zkpytorch}, and
pairing- or Plonk-based systems such as vCNN~\cite{vcnn}, ZEN~\cite{zen},
ZENO~\cite{zeno}, ZKML~\cite{zkml}, EZKL~\cite{ezkl} and
Bionetta~\cite{bionetta}. Mystique~\cite{mystique} is an interactive, VOLE-based
alternative. For LLMs they include zkLLM~\cite{zkllm}, zkGPT~\cite{zkgpt},
DeepProve~\cite{deepprove}, ZKTorch~\cite{zktorch} and Jolt Atlas~\cite{joltatlas}.
These systems give computational soundness and small proofs,
but their provers are far slower than inference: from half a second for LeNet-5 to
minutes or hours per query for larger models.

\para{Checks when the verifier knows the weights.} SafetyNets~\cite{safetynets} uses
interactive proofs for networks with quadratic activations. Slalom~\cite{slalom}
checks every linear layer of a GPU computation from inside an SGX enclave with
Freivalds' algorithm, optionally with a precomputed secret challenge.
Maverick~\cite{maverick} applies sparse Freivalds checks and a linear code to LLM
inference, for a client that has preprocessed the weights. LAMP~\cite{lamp}, by contrast,
lets a verifier that holds only a commitment check a single matrix product, combining
Freivalds' check with proximity testing.

\para{Sampling, fingerprints and optimistic protocols.} Anchuri et
al.~\cite{anchuri2026verifiable} spot-check random paths and argue security through
trace separation; SLP~\cite{slp} samples which layers receive a SNARK. TOPLOC~\cite{toploc}
and SVIP~\cite{svip} fingerprint hidden states, with empirical guarantees.
Verde~\cite{verde}, opML~\cite{opml} and TAO~\cite{tao} resolve disputes and need an
honest party or a challenger.

\para{Where we fit.} Our defence combines two known building blocks, Freivalds' check
(as in Slalom and Maverick) and a linear-code weight commitment (as in Ligero and LAMP),
into an end-to-end protocol for whole CNNs and transformers with committed weights, the
setting of~\cite{anchuri2026verifiable}. What is new here is (i)~the attack and the analysis showing why the sampling approach cannot reach
full soundness, (ii)~the complete protocol: exact integer graphs, non-weight operations
recomputed by the verifier, and parameters derived from $\lambda$, and (iii)~a
comparison on the same models as the original paper and the zkSNARK literature.

\section{Technical Approach}

\subsection{Setting and threat model}
A model $M$ has a public architecture and secret or public weights. Before any query, a
commitment $C_M$ to the weights is computed correctly and given to the client, for
example by the model owner. As in~\cite{anchuri2026verifiable}, we assume this step is
honest. The client sends a query $x$. The provider returns a claimed output $y$ and a
proof. The provider may deviate arbitrarily. We want \emph{completeness}: honest
answers are always accepted. We also want \emph{full soundness}: any $y \neq M(x)$ is
rejected except with a small probability~$\varepsilon$. The original paper proves a
weaker notion, \emph{other-model soundness}, in which the adversary must honestly run
some different model. We consider three trust settings. In \textbf{C} the client holds
only $C_M$ (32 bytes per weight matrix), as in~\cite{anchuri2026verifiable} and the
zkSNARKs. In \textbf{K} the client knows the weights. \textbf{Kpre} is K with a secret,
precomputed challenge, as in Slalom and Maverick.

\subsection{The original protocol and our attack}
\label{sec:attack}
In the protocol of~\cite{anchuri2026verifiable} (``RandPathTest''), the prover commits
to every activation $a_j$ of the forward pass with a Merkle tree. The verifier then picks
a random output neuron and walks back to the input, picking a random parent at each
layer. At every node $j$ on the path it opens the parents' activations and the weights
$w_{ij}$ from $C_M$, and checks the local relation
$a_j = \phi\big(\sum_{i \in G_j} w_{ij} a_i\big)$, where $G_j$ is the set of parents
of $j$ and $\phi$ the activation. One path costs one weight row per layer, which is why
proving is so cheap.

\para{The single-neuron attack.} Our adversary runs the correct model on $x$ and picks
one neuron $j$ in some layer. It replaces $a_j$ by a value chosen so that the output
becomes the target (a wrong class, or any class the attacker wants). It then recomputes
all later layers \emph{with the true weights}. Every node above $j$ is consistent with
its parents, and every node below $j$ is untouched, so exactly one node in the whole
trace is wrong. The verifier notices only if its path visits $j$. This happens with
probability $1/N$ in a layer of width $N$, or $1-(1-1/N)^s$ with $s$ paths. Applied only
to inputs that contain a trigger, the attack becomes a backdoor. Clean answers are
bit-for-bit the honest ones, so the clean-accuracy gap is exactly zero.

\para{Why sampling more cleverly cannot fix it.} A natural fix is to sample ``where it
matters'' instead of uniformly. We prove that this cannot help for rules that ignore
the claimed values, and give a counterexample for the natural rule that uses them.

\begin{theorem}[uniform sampling is minimax-optimal]
Consider any sampler whose choice of nodes does not depend on the claimed trace and
that opens at most $s$ nodes of a layer. Let $U$ be the neurons of that layer whose
change can flip the output, and $q(v)$ the probability that node $v$ is opened. An
adversary who knows the sampler tampers with the least-visited node in $U$, so
detection is at most $\min_{v\in U} q(v) \le s/|U|$. Equality holds only when $q$ is
uniform on $U$.
\end{theorem}

\noindent The bound follows because the minimum is at most the average, and the $q(v)$
sum to at most $s$. Constant detection therefore needs $s=\Omega(|U|)$ openings per layer,
which is linear in the width: exactly the cost the protocol was built to avoid. Samplers
that \emph{do} look at the claimed values fare no better in the worst case. The most
effective one we found against the naive attack steps to parent $i$ with probability
proportional to its contribution $|w_{ij} a_i|$. It gives weight zero to any neuron whose
claimed activation is zero. The adversary therefore flips the output by setting a few
neurons to exactly zero, and its detection is exactly $0$. Adding a floor $\varepsilon$
to every claimed activation, $|w_{ij}|(|a_i|+\varepsilon)$, restores some detection (at
best $10\times$ uniform, i.e.\ 2\%, at $\varepsilon=1$; 0.9--6$\times$ for other
floors), but it stays at a few percent.

\subsection{Our defence: checking every layer at once}
\label{sec:defence}

Instead of checking a few neurons exactly, the verifier checks \emph{one random
combination of all the neurons of a layer}: a wrong value anywhere in the layer changes
it, except with negligible probability. We build this up in four steps.

\para{Step 1: an exact integer model.} A random combination is only a reliable test if
both sides compute exactly the same numbers, so the model runs in integers. Following
standard integer-only inference~\cite{jacob2018quant}, each weight layer computes
$Z = W X + b$, where $W$ is int8 with one scale per output channel, $X$ is int8 with
one scale per tensor, and BatchNorm is folded into $W$ and $b$. The next layer's input is obtained by
fixed-point requantisation followed by the usual activation or pooling. Convolutions
become matrix products through im2col. The prover's GPU computes these products in
float32 chunks of at most 1{,}024 terms; every partial sum stays within $2^{24}$ and is
therefore exact, so the GPU result is bit-identical to the client's CPU. This also
removes the floating-point tolerance that the original protocol needs, which in our
reproduction was mandatory and gave the attacker a free budget.

\para{Step 2: only weight products need a proof.} For every weight layer $\ell$ the
prover sends the claimed pre-activations $Z_\ell$ (the \emph{claims}). Everything that
does not involve the weights, the verifier computes itself from values it has already
checked: requantisation, ReLU, pooling, residual additions, LayerNorm/RMSNorm,
GELU/SiLU (by table lookup), RoPE, softmax, and the attention products $QK^\T$ and
$PV$ (with $P$ the attention weights). So the input $X_\ell$ of every weight layer is
always the verifier's own, and the
only thing left to check is $Z_\ell = W_\ell X_\ell + b_\ell$. Because the verifier
builds each $X_\ell$ from the previous layer's checked claims, the layers are chained:
a prover cannot answer one layer consistently and feed a different value into the next.

\para{Step 3: Freivalds' check.} Write $A_\ell = [W_\ell \,|\, b_\ell]$, a matrix with
$N$ rows (one per output neuron) and row length $k$, and let $T$ be the number of
columns of $X_\ell$ (pixels or tokens). The verifier draws a random vector
$\chi \in \F^{N}$, one entry per output neuron, and checks
\begin{equation}
  \chi^\T Z_\ell \;=\; \underbrace{(\chi^\T A_\ell)}_{u_\ell}\,[X_\ell; \mathbf{1}] .
  \label{eq:freivalds}
\end{equation}
Why does this catch every error? Let $D = Z_\ell - A_\ell [X_\ell; \mathbf{1}]$ be the
difference between the claims and the truth. The two sides of~\eqref{eq:freivalds}
differ by $\chi^\T D$. If $D$ has a non-zero entry in row $i$ and column $m$, then entry
$m$ of $\chi^\T D$ equals $\chi_i D_{im}$ plus terms that do not involve $\chi_i$. For
any values of the other entries, exactly one value of $\chi_i$ makes it zero, so a
wrong layer passes with probability at most $1/p$. With $r$ independent vectors this
drops to $p^{-r}$. It does not matter how many values are wrong or where they are: one
neuron or all of them is caught equally well. The check is also cheap: both sides cost
$O((N+k)T)$, against $O(NkT)$ for recomputing the layer.

We work in the BabyBear field $\F$ with $p = 15\cdot2^{27}+1 \approx 2^{31}$, which
makes the argument exact (no rounding, no overflow). The verifier range-checks every
claim ($|z| < 2^{29}$), and when the model is committed we check that honest values are
in the same range ($128\sum_j |w_{ij}| + |b_i| < 2^{29}$ for every row). A wrong claim
and the true value then differ by less than $2^{30} < p$, so they are always different
field elements.

\para{Step 4: committed weights.} In setting C the verifier does not have $A_\ell$, so
it cannot compute $u_\ell = \chi^\T A_\ell$; the prover sends it. The remaining question
is how the verifier can trust $u_\ell$ while holding only a 32-byte commitment. Checking
a few entries of $u_\ell$ against the weights would be weak: a prover who changes one
of the $k$ entries escapes a check of $t$ random entries with probability $1-t/k$. We
therefore commit to an \emph{encoded} copy of the weights, in the style of
Ligero~\cite{ligero}. When the model is published, every row of $A_\ell$ is padded
with zeros to a power of two $\bar k \ge k$ and Reed--Solomon
encoded~\cite{reedsolomon1960} to length $n = 4\bar k$, giving a matrix $\hat A_\ell$. The commitment $C_M$ is a Merkle root~\cite{merkle1987} over the
$n$ columns of $\hat A_\ell$, 32 bytes per weight matrix. Encoding is linear, so
$\chi^\T \hat A_\ell = \enc(\chi^\T A_\ell)$: the combination of the encoded rows is the
encoding of the true $u_\ell$. The verifier encodes the claimed $u_\ell$ itself, picks
$t$ random column positions $j$, and checks $\chi^\T \hat A_{\ell,j} = \enc(u_\ell)_j$
on the opened columns. If $u_\ell$ is wrong, $\enc(u_\ell)$ and $\enc(\chi^\T A_\ell)$
are two different Reed--Solomon codewords, which agree on at most $k-1$ of the $n$
positions. The code has spread any change over at least three quarters of the
positions, so each opened column catches a wrong $u_\ell$ with probability at least
$3/4$, and $t$ distinct columns leave at most $((k-1)/n)^t \le 4^{-t}$.

\para{The complete protocol.} Setup happens once per model: the owner encodes and
commits the weights and publishes $C_M$. Then, for each query
(Figure~\ref{fig:protocol}):
\begin{enumerate}
  \item The client sends $x$.
  \item The prover runs the integer model and returns the output $y$ and the claims
  $Z_\ell$ of every weight layer.
  \item The verifier range-checks the claims, recomputes every non-weight operation
  (obtaining each $X_\ell$ and checking that it leads to $y$), and draws $r$ random
  vectors $\chi$ per layer.
  \item The prover returns $u_\ell = \chi^\T A_\ell$ for every layer.
  \item The verifier checks~\eqref{eq:freivalds} for every layer and draws $t$ random
  column positions.
  \item The prover opens those columns of every $\hat A_\ell$ with one Merkle multiproof
  per matrix; the verifier checks the Merkle paths against $C_M$ and the column
  equations.
\end{enumerate}
The verifier accepts only if every check passes. The order matters: the claims are
fixed before $\chi$ is drawn, and $u_\ell$ before the columns are chosen, so the prover
can never adapt a wrong value to the randomness that will test it.

\begin{theorem}[soundness]
If $C_M$ is honest and the prover cannot find a SHA-256 collision, then for any claimed
$y \neq M(x)$ the verifier accepts with probability at most
$\varepsilon = \sum_\ell \big[\,p^{-r} + \big(\tfrac{k_\ell - 1}{n_\ell}\big)^{t}\,\big]$.
\end{theorem}

\noindent\emph{Sketch.} If $y \neq M(x)$, some claim is wrong; let $\ell$ be the first
layer with a wrong claim. Its input $X_\ell$ is correct, because the verifier computed
it from correct claims. If $u_\ell$ is correct, \eqref{eq:freivalds} fails except with
probability $p^{-r}$ (Step~3). If $u_\ell$ is wrong, a column check fails except with
probability $((k_\ell-1)/n_\ell)^t$ (Step~4). A union bound over the layers finishes the
proof. \qed

\smallskip
The guarantee needs no assumption about how models behave (no trace separation) and no
trusted setup; in setting C it relies only on a collision-resistant hash for the Merkle
tree. For a target $\lambda$ we set $\beta = \lambda + \log_2(2L)$ for $L$ weight
layers, and use $r = \lceil \beta/\log_2 p \rceil$ repetitions and
$t = \lceil \beta/2 \rceil$ columns for every layer (enough because $n \ge 4k$ makes
$(k-1)/n < 1/4$), which makes $\varepsilon \le 2^{-\lambda}$.
For VGG-16 this means $r{=}5$, $t{=}67$ at $\lambda{=}128$, and $r{=}2$, $t{=}23$ at
$\lambda{=}40$. The protocol can also be made non-interactive by deriving the challenges
from the transcript with SHAKE-256 (Fiat--Shamir~\cite{fiatshamir1986}), with 64 extra
bits against a prover who retries many times. When the client knows the weights
(setting K) it computes $u_\ell$ itself and steps 4 and 6 disappear. In Kpre the secret
$\chi$ and $u_\ell$ are computed once per model, so the proof is just the claims. There
$\chi$ exists before the claims but stays secret, so the claims are still independent of
it: each query is falsely accepted with probability at most $\sum_\ell p^{-r}$, and $q$
queries with the same $\chi$ with probability at most $q\sum_\ell p^{-r}$.

\para{Costs.} The prover runs the forward pass, computes $u_\ell$ and opens $t$ columns.
It does not store the encoded weights, and recomputes each opened column from $W_\ell$,
so its extra work is $O((r+t)\sum_\ell N_\ell k_\ell)$, independent of the number of
pixels or tokens. The verifier does $O(r\sum_\ell (N_\ell + k_\ell) T_\ell)$ work for
the Freivalds checks, $O(rt\sum_\ell (N_\ell + k_\ell))$ work plus the hashing of the
opened columns for the column checks (setting C only), and the non-weight operations.
The proof holds the claims, $4\sum_\ell N_\ell T_\ell$ bytes (the size of the
pre-activations), plus $4r\sum_\ell k_\ell$ bytes for the $u_\ell$,
$4t\sum_\ell N_\ell$ bytes for the opened columns, and the Merkle hashes. Only the claims
grow with the input, so the columns are the largest part for small images and short
prompts, and the claims for large images and long prompts. Unlike the proofs of zkCNN or
zkLLM, which stay at a few hundred kilobytes, ours grows with the activations.

\subsection{Implementation}
Everything is written in Python and PyTorch; the prover runs on a GPU and the verifier
on a CPU. Field arithmetic uses exact limb decomposition, Reed--Solomon encoding an NTT,
and Merkle trees SHA-256 with multiproofs. As a baseline, the original protocol is
re-implemented on the same integer graphs, with exact visit probabilities computed by
dynamic programming. The code has 214 tests.

\section{Results}

\subsection{Experimental setup}
\para{Models.} We use the models that prior work reports on. LeNet-5 (MNIST) and VGG-11,
VGG-16 and ResNet-18 (CIFAR-10) are the CNNs of zkCNN, ZKML, ZENO, Bionetta and
EZKL. A 224$\times$224 ResNet-18 dog-vs-cat classifier, trained on ImageNet's dog and
cat classes (\cite{anchuri2026verifiable} used Kaggle's Animals-10), plays the role of
their model, and a dog-vs-squirrel ResNet-18 (also from ImageNet) that of their
substitute $\tilde M$. The MNIST MLP (784--512--256--10) is the network of our
attack experiments. We trained all of them ourselves and quantised them to int8. The
int8 accuracy is within 0.4 points of the float model for every model. For language models we use the exact shapes of GPT-2, OPT-125M/1.3B/6.7B,
Llama-2-7B/13B and Qwen3-4B with random int8 weights, since the costs depend only on the
shapes. Every decoder is built in full except Llama-2-13B, whose int8 weights exceed
our 11\,GB GPU; it is extrapolated linearly from 1- and 2-block builds. On the full
builds, the rule gave the proof size within 0.02\% and the prover within 12\%, but the
C verifier at short prompts up to 48\% too low. Streaming the claims to the host lets
the 7B models fit at 2{,}048 tokens (claims of 10--11\,GB; Llama-2-7B peaks at
7.3\,GiB).

\para{Hardware and baselines.} The prover is one NVIDIA \ProverGPU. The verifier is
\VerifierThreads{} threads of an \VerifierCPU{} on the university's SLURM cluster; times are
medians over the queries of a run. We compare with
(i)~the original protocol run on the same graphs and machine, and (ii)~the published
results of 17 systems, taken as reported with their own hardware and each checked
against the source paper. The benchmark is stored as raw records (78{,}266), from which
Tables~\ref{tab:cnn}--\ref{tab:ratios} and Figures~\ref{fig:security}--\ref{fig:llm} are
generated; the MNIST experiments of Section~\ref{sec:break} store theirs in
\texttt{code/artifacts/results}, with the trained models.

\subsection{Breaking the original protocol}
\label{sec:break}

\para{Reproduction.} Our implementation behaves as the paper describes. Over four
substitute-model settings from the paper, honest provers were accepted in 100\% of
3{,}000 runs each, and substitute models were caught 99.8--100\% of the time, even an
8-bit quantised copy that agrees with $M$ on all 150 evaluated queries. We also found that
the idealised exact-equality check accepts an honest prover only 21--37\% of the time,
because a whole-layer matrix product and a single-neuron dot product round differently.
The tolerance of $10^{-4}$ that the paper prescribes is therefore mandatory, not
optional.

\para{The attack works.} Table~\ref{tab:attack} lists, for each attack, how many of the
778 trace nodes are wrong and the probability that the verifier accepts, computed
exactly by dynamic programming over the paths. Each row is averaged over 8 test queries
for the first six rows, and over the successful attacks on 40--100 test queries for the
last three. The attacks
of~\cite{anchuri2026verifiable} (a substitute model, the inverse-transform and logit-swap
forgeries of its Appendices E and F, and the gradient reconstruction of its Section~7.2)
try to make many nodes \emph{almost} right, and are always caught. Changing a
single neuron is accepted 99.6--99.8\% of the time, exactly the $1-1/N$ we predict for
layers of 256 and 512 neurons. As a backdoor (a $3{\times}3$ bright patch as trigger),
it serves the honest output on 100\% of clean queries and succeeds on 100\% of the
triggered queries not already in the target class. The real protocol accepted it in
99.96\% of 2{,}300 runs (the exact prediction is 99.8\%). A stealthy
variant keeps every forged value inside that neuron's natural range (up to its 95th
percentile), so a range check would not flag it. It needs only about 3--5 changed
neurons and is still accepted about 99\% of the time. More paths do not
help much either: with 250 paths, a 250-fold larger proof, the attack is still accepted
61\% of the time.

\para{Smarter sampling does not help.} Measured against an adversary who knows the
rule, uniform sampling detects 0.20\% of attacks. Static importance weighting drops to
0.11\%, and gradient-saliency weighting, which a verifier cannot even compute without
the full model, to 0.016\%. Contribution weighting detects nothing: zeroing about 14 of
512 neurons flips the prediction, and the real protocol accepted 2{,}000 of 2{,}000 runs
(last row of Table~\ref{tab:attack}).
Zero is also the most common natural activation (65\% of inputs for these neurons), so
no statistical check flags it.

\para{The same holds on larger models.} On every CNN, changing one penultimate neuron
flips 100\% of predictions. One path catches it with probability 1/84 (LeNet-5) to
1/512 (VGG, ResNet), and the least-visited neuron is caught with probability as low as
1/28 million (orange bars in Figure~\ref{fig:security-detect}). Reaching $2^{-40}$ takes
2{,}316--14{,}182 paths, which opens every committed row: the proof becomes the whole
model plus the trace. The last three columns of Table~\ref{tab:cnn} give these paths
and bytes, next to our proof at $\lambda{=}40$. On Llama-2-7B one path detects 1/11{,}008 of
single-neuron attacks, and $2^{-40}$ needs about 305{,}000 paths, i.e.\ the entire model
and trace ($\approx$13.7\,GB with the fp16 weights of~\cite{anchuri2026verifiable}).

\subsection{Our defence catches every attack}
\label{sec:security}
Across every model, mode and security level, our verifier accepted all 5{,}547 honest
queries. It rejected all 1{,}854 attacks on the image models, all run at the weakest
setting ($\lambda{=}40$, committed weights). These were: one changed value, one changed
penultimate neuron (red bars in Figure~\ref{fig:security-detect}), one changed logit, 1\% of the weights perturbed, the substitute
model $\tilde M$, and two forgeries built so that only one specific check can stop them.
It also rejected all 602 attacks on the language models: a $+1$ on one middle-layer
pre-activation in every run (137; Llama-2-13B only on its 1- and 2-block builds) and, on
the full OPT-1.3B, Qwen3-4B, OPT-6.7B and Llama-2-7B at the image models' setting, 150
each of one changed value, penultimate neuron and logit, and 15 blocks with 1\% of the
weights perturbed. Freivalds' check fired in 2{,}344 cases. The Reed--Solomon column check caught all 56 forged $u_\ell$
vectors, and the Merkle check all 56 forged columns, so every part of the protocol is
needed and works.

Figure~\ref{fig:security-bits} shows the trade-off between security and bytes sent. The
dotted curves are the original protocol with $1, 2, \dots$ paths: they rise slowly and
reach $2^{-40}$ only when nearly the whole model is opened (the vertical lines). Our
solid lines join the points for $\lambda = 40, 80, 128$. Because $r$ and $t$ are rounded
up and rows are padded, the achieved security exceeds the target: 48--58 bits at
$\lambda{=}40$ (67\,kB--10.7\,MB) and 150--153 bits at $\lambda{=}128$
(131\,kB--12.1\,MB).

\subsection{Cost}
\label{sec:cost}


\para{Image models.} Table~\ref{tab:cnn} gives the int8 accuracy of each model and our
cost in settings C and Kpre. With committed weights our prover needs
8--96\,ms per query, the verifier 15--375\,ms, and the proof is 131\,kB--12.1\,MB.
That is 4--8$\times$ the known-weights prover, which only runs the integer forward
pass. For the VGGs and the CIFAR ResNet
the proof is 2.4--4.4$\times$ smaller than the int8 model. For the 224-pixel ResNet it
is about the size of the model (12.1 vs.\ 11.2\,MB), because the activations of a
large image are big.


\para{Language models.} Table~\ref{tab:llm} shows the same picture at LLM scale, for the
next-token logits of one prompt. GPT-2
with a 64-token prompt is proved in 0.43\,s and verified in 0.92\,s with a 62\,MB proof.
Llama-2-7B takes 7.9\,s and 7.3\,s with a 762\,MB proof, about 9$\times$ smaller than
its int8 weights. At 2{,}048 tokens Llama-2-7B takes 36\,s to prove, but the proof
grows to 11.6\,GB and verification to 3.7 minutes, since the verifier recomputes
attention over all token pairs. With known weights (Kpre) the proof is only the
claims, for example 21.8\,MB for GPT-2 and 349\,MB for Llama-2-7B at 64 tokens.
The committed-weights prover takes 1.2--2.1$\times$ the known-weights one at 2{,}048
tokens and 10--15$\times$ for billion-parameter models built in full at 64 tokens or
fewer, where opening the weights dominates.

\section{Discussion}

\para{What this means.} Sampling-based proofs of inference are only as strong as the
adversary is weak. They catch a provider who honestly runs the wrong model. They do not
catch one who runs the right model and edits the answer, and no sampling rule we
analysed closes that gap cheaply. Our defence shows that full soundness does not need
zkSNARK-level prover cost: checking each weight layer with a random linear combination
adds a fixed amount of work per query (Section~\ref{sec:cost}), far below zkSNARK
provers, and gives a $2^{-\lambda}$ guarantee with no trusted setup and no assumption
about how models behave. It suits settings where the
client has a capable machine and a fast link, for example an enterprise gateway or an
auditor who checks a random fraction of queries. It is also most attractive for large
models with short prompts, where the proof is much smaller than the model.

\para{Limitations.} (i)~The proof grows with the activations: megabytes for the image
models, and gigabytes for 7B models at long prompts, where zkLLM's proofs stay below
200\,kB.
(ii)~Our verifier recomputes attention and other non-weight operations, so its cost
grows with the square of the prompt length. (iii)~The check is exact, so the provider
must serve the integer model. For our CNNs this changed accuracy by at most 0.4 points,
but we did not measure the quality of int8 LLMs: their costs were measured with random
weights, and Llama-2-13B's were extrapolated (its C verifier time is likely too low). (iv)~Like the original protocol, we assume
that the weight commitment is honest. (v)~The protocol is not zero-knowledge: the opened
columns reveal a few random linear combinations of each weight row. (vi)~Our prototype
is Python, not optimised native code.

\para{Future work.} The largest gains would come from (1)~compressing the claims, for
example with a sum-check argument for the non-weight operations or batching several
queries against one set of openings; (2)~an optimised verifier (native code, or a GPU);
and (3)~support for token-by-token generation with a KV cache. Before any wider
publication, we intend to share the attack with the authors
of~\cite{anchuri2026verifiable}.

\section{Conclusion}

We studied a recent lightweight proof of inference, which checks a model's computation
along one random path. We showed that a single tampered neuron defeats it, with
99.8\% acceptance and zero cost on clean inputs, and that the smarter sampling rules we
analysed do not help. We then built a defence that checks every layer at once with
Freivalds' algorithm against a Reed--Solomon/Merkle commitment to the weights. It
catches any wrong value with probability $1-2^{-\lambda}$. It rejected every one of
2{,}456 attacks on models from LeNet-5 to Llama-2-13B, and its prover is one to four
orders of magnitude faster than zkSNARK provers on the same models (as reported on their
own hardware). The main takeaway is that
checking \emph{everything}, cheaply and algebraically, beats checking a few things
exactly.
