\title{Certified but Compromised: Breaking and Fixing\\ Lightweight Proofs of Inference\ifdefined\pviextended\\ (Extended Version)\fi}

\author{\IEEEauthorblockN{Anonymous Authors}
\IEEEauthorblockA{Submission under double-blind review}}

\maketitle

\begin{abstract}
Lightweight proofs of inference check a sample of a committed execution trace. This is not fully sound. A provider that overwrites one neuron and recomputes the later layers honestly leaves one inconsistent site, which the path protocol of Anchuri et al.\ misses with probability $1-1/N$ per path in a layer of width $N$; on OPT-6.7B, one edited neuron changed the next token for \AttackOptLSucceeded{} of \AttackOptLPrompts{} prompts. We prove that every verifier making $q$ queries per layer to a hiding weight commitment of locality $d$, even an adaptive one reading the query's whole trace, accepts such a forgery on some network with probability at least $1-qd/N$, while a linear-code commitment, whose queries mix all rows, reaches $2^{-\lambda}$ with $O(\lambda)$ queries. Our defence checks every matrix product of an exact int8 model with the evaluation protocol of a linear-code polynomial commitment, using only a hash function. It lets a client without weights or GPU check an untrusted provider of an open-weight model, and a CPU
client verifies a 2{,}048-token Llama-2-7B prompt \CpuRatioN{} times faster than the fastest exact re-execution on the same CPU (non-interactive, full model) \todo{EPYC: ``at least N times''}. A variant makes 2{,}048-token proofs \VOneRatioRandom{} times smaller with random weights and \VOneRatioRealOptL{} times with the real OPT-6.7B, but proofs still grow with the prompt.
\end{abstract}
