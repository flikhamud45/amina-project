\section{Discussion and Limitations}
\label{sec:discussion}

\para{Options for a client.} Of the options in Table~\ref{tab:options}
(Section~\ref{sec:eval-reexec}), a GPU TEE is cheapest if the client trusts the vendor's hardware,
attestation and side-channel resistance. A client with the weights and a GPU should re-execute.
zkLLM hides the weights but proves for minutes, and CommitLLM is cheap but statistical. Our
protocol serves a client with neither the weights nor a GPU that will not trust hardware: in mode
$\sC$ it holds 32 bytes per matrix and checks a 64-token proof, about 21$\times$ smaller than the weights, in about a second on
a CPU. For the provider, proving costs 4.1--8.6$\times$ our exact forward pass without proofs and
19--40$\times$ an fp16 one on the same GPU (OPT-1.3B, 2{,}048 tokens; Section~\ref{sec:eval-cost}).
A provider may also serve with the exact model and prove later, on request, with the same proof.

\para{Proof size.} The proof carries every weight operation's output, so it grows with the prompt.
For Llama-2-7B it reaches the size of the int8 weights at about 2{,}050 tokens without V1 and, by
the byte model, at about 4{,}500 with it. Without V1, a client thus receives more bytes than
the weights after one long prompt or about 21 short ones, and gains only if it cannot run the
model. Committing the activations, as zkLLM does, would remove this growth.

\para{Weights and trust.} The protocol is not zero-knowledge: the claims of about
$\lceil k/T\rceil$ queries reveal a weight matrix with rows of length $k$. It therefore targets
open-weight models. For private weights it shares the limitation that Hollow-LLM shows for
zkSNARKs~\cite{hollowllm}. The setup proof is untimed \todo{F6}.

\para{Scope.} We evaluate dense decoders on prompts up to 2{,}048 tokens; mixture-of-experts
models and longer contexts are untested. Costs use random weights, which real OPT weights match
(Section~\ref{sec:eval-setup}), and the quality of the
integer OPT-6.7B and Qwen3-4B, and at long context, is unmeasured \todo{F2a, F2b}.

\para{The attack and the bound.} Condition (H) holds for random ensembles with independent rows
and on the constructed worst case, not on trained networks, where we report the best attacks found.
On OPT-1.3B and OPT-6.7B, edits that keep every value inside ranges calibrated on held-out text still
succeed, also against contribution weighting (Section~\ref{sec:break}).

\section{Conclusion}
\label{sec:conclusion}

Spot-checking an unencoded execution trace is not fully sound: an edit followed by honest
recomputation is the honest trace of a model that differs in one row, which in the worst case no
adaptive or value-aware sampler finds faster than uniform sampling. Our defence therefore encodes the
model and checks every weight operation of an exact integer model with Freivalds' algorithm against a
Reed--Solomon and Merkle commitment, using only a hash function and a linear code. Its cost is a
proof that grows with the prompt.
